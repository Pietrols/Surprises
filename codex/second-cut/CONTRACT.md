# Implementation contract v1

Static native JS ES modules; no runtime dependencies. Internal dimensions are integer tenths of a millimeter; UI converts mm × 10. All IDs strings; no unsafe HTML from input.

Stock = {id, revision: integer >=0, label, width, height, thickness, material: string, grain: 'x'|'y'|'none', allowRotation: boolean}. Each stock is ONE physical piece. Width,height,thickness positive safe integers, maximum width/height 100000 (10 m), thickness <=1000. Max 40 stock pieces. Width*height safe integer. Inputs are usable rectangles after any trimming; do not account for gross trims.
Settings = {kerf: integer 0..100, tools: string[]}; tool IDs: 'saw','glue','clamps','sandpaper'. No trim input this release; clearly say measured usable dimensions.
Part = {id,label,width,height,grain: 'x'|'y'|'any'}; width/height in recipe orientation. Recipe parts share candidate material/thickness. Rotation changes grain axis. Stock grain 'none' ignores part grain; stock allowRotation false still forbids 90° rotation.
Tree nodes:
- {type:'cut', axis:'x'|'y', at:integer, kerf:integer, first:Node, second:Node} where at is relative to current region origin, first size at, second size dimension-at-kerf. Child sizes must be >0; avoid terminal edge cuts by exact fit. A trailing gap smaller than kerf cannot fit a part unless exact; no implicit edge trimming.
- {type:'part', partId:string, rotated:boolean}
- {type:'remnant'}
Tree geometry derives from roots; no coordinates in nodes.
Candidate = {id,recipeId,recipeVersion:1,title,description,width,depth,height,quantity:integer,thickness,material,parts:Part[],trees:[{stockId,revision,root:Node}],requiredTools:string[],instructions:string[],metrics:{stockArea,partArea,kerfArea,remnantArea,cuts,utilization},searchNote:string}. Dimensions exterior per object; quantity instances in parts with unique IDs. Trees ONLY consumed stock. id stable for same search inputs. Candidates mutually exclusive.

recipes.js exports enumerateRecipes(stocks,settings) -> finite candidates WITHOUT trees/metrics; recipes cover 2 joinery-checked families (tray/compartment box) and simple square tile set; ranges finite; quantities 1 and 2 when practical; no structural claims. Grain on parts may be 'any' except walls grain x. Version and exact inset-floor joint formulas. Reject incompatible tools. Never mix thickness/material in one candidate.
engine.js exports findPlans(stocks,settings,{maxPlans=12,maxNodes=25000}={}) -> {plans:Candidate[],examined:number,exhausted:boolean}; deterministic bounded multi-order greedy/backtracking guillotine heuristic, no infeasibility/optimality claim. Also exports planParts(stocks,parts,settings,{maxNodes=25000}={}) -> {trees,metrics,exhausted}|null for independent test fixtures. Must validate stock/settings before expensive work. Cancellation is worker termination by UI. worker.js uses onmessage {id,stocks,settings}, returns {id,result} or {id,error}; findPlans calls independent validatePlan on EVERY result and drops/reports invalid results as error (do not silently accept). No runtime cycles.

validate.js exports validatePlan(plan, stocks, settings) -> {ok:boolean,errors:string[],metrics:{stockArea,partArea,kerfArea,remnantArea,cuts,utilization},placements:[{partId,stockId,x,y,width,height,rotated}],remnants:[{stockId,x,y,width,height}],cuts:[{stockId,x,y,width,height,axis,at,kerf,order}]}. Reconstruct independently; reject missing/duplicated IDs, parts, stock, wrong revisions, grain, dimensions, unknown tree shapes, material/thickness mismatches, missing tools and kerf mismatches, depth>200 and nodes>10000. Invalid input returns ok:false not uncaught exception. Metrics ignores supplied candidate metrics; UI uses validator metrics. All parts must appear exactly once. Root trees reference real stocks.

inventory.js exports validateInventory(stocks) -> {ok,errors}; parseStockText(text, defaults) -> Stock[] or throws clear Error, supports '500x300x2, 420x180' in MM (x optional qty), lines/semicolon/comma, decimal sizes allowed to 0.1mm; defaults {thickness integer,material,grain,allowRotation}. Assign crypto.randomUUID IDs in browser/Node. Bounds above. Exports commitBuild(stocks,plan,settings) -> {stocks, transaction:{before:Stock[],after:Stock[],planId}}; validator required; consumes referenced stock only; preserves non-consumed stocks; retains remnants >= 300 units in BOTH dimensions, inherited orientation/material; IDs new, revisions0. Reject if result >40 stocks. undoBuild(stocks,transaction) -> Stock[] rejects if current stocks differs from transaction.after; deep snapshots. Transactions are JSON serializable. Imports validate full array before replacing data, UI owns persistence.

Root integration owns UI and README. Other agents only assigned modules/tests. Test filenames unique. Use node:test. No files in peer-owned folders.
